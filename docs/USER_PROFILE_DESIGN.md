# 对话人画像设计

> 状态：**A1 / A2 已实现**（字段、校验、注入、回写更新），A3 之后待做。
> 关联：[日程、事件量级与状态归属](SCHEDULE_EVENT_DESIGN.md)

## 为什么需要

角色现在每次只能看到「对方最后说了什么」+「是否在睡/在外」。这决定了主动消息只能做
即时反应，做不出“你该睡了”“今天不是要早起吗”这类基于长期了解的话。

画像要解决的是：**让角色知道对方是谁，而不只是对方刚才说了什么。**

## 现状

```json
"user": {
  "user_id": "…",
  "sleeping": false,
  "away": "",
  "place": "",
  "last_text": "",
  "updated_at": 0
}
```

只有临时状态，没有任何稳定事实。

## 记录范围

按“是否由用户明确表达”和“是否有实际用途”两条线划分。

### 记录

| 类别 | 字段 | 例子 | 用途 |
| --- | --- | --- | --- |
| 称呼 | `display_name` / `address_as` | “叫我小满就行” | 主动消息称呼 |
| 位置 | `city` / `timezone` | “我在杭州” | 天气、作息、时区换算 |
| 职业 | `occupation` | “我是做设计的” | 理解作息和话题 |
| 作息 | `usual_sleep` | “我一般十二点睡” | 决定什么时候不该打扰 |
| 兴趣 | `interests[]` | “最近在练吉他” | 开新话题 |
| 生活理念 / 价值观 | `values[]` | “我觉得人得先照顾好自己” | 避免说教、呼应立场 |
| 健康状态 | `health[]` | “最近感冒了” | 关心，但不诊断 |
| 重要日期 | `important_dates[]` | “下周三面试” | 到时问候 |
| 偏好 / 禁忌 | `dislikes[]` | “别叫我小朋友” | 避免踩雷 |

### 不记录

| 类别 | 原因 |
| --- | --- |
| 政治立场 | 高风险、易误判、没有使用场景 |
| 宗教信仰 | 同上 |
| 收入 / 财务 | 没有使用场景，且高度敏感 |
| 证件、账号、密码、住址门牌 | 安全 |

### 健康状态的处理

按讨论结论，健康**要记录**，但要带使用边界：

1. **只记录用户明确说出的**（“我感冒了”“最近胃不舒服”），不做推断（不写“他可能抑郁”）。
2. 每条带 `source`（原话）、`since`（开始日期）、`status`（`ongoing` / `recovered`）。
3. 角色可以关心（“药吃了吗”“今天好点没”），但**不得诊断、不得给医疗建议、不得夸大严重性**。
4. 恢复途径只有两个：用户说好了，或超过 14 天自动降级为 `recovered`。
5. 面板上标为敏感项，和普通偏好区分显示。

## 数据结构

```json
"user": {
  "profile": {
    "display_name": "",
    "address_as": "",
    "city": "",
    "timezone": "",
    "occupation": "",
    "usual_sleep": "",
    "interests": [],
    "values": [],
    "dislikes": [],
    "important_dates": [],
    "health": [
      {"text": "最近感冒", "since": "2026-11-10", "status": "ongoing", "source": "我感冒了"}
    ],
    "notes": "",
    "updated_at": 0
  },
  "observations": [
    {"at": 0, "kind": "preference|health|value|plan", "fact": "", "source": ""}
  ]
}
```

- `profile` 是长期事实，只有明确陈述才写入
- `observations` 是短期观察（“明天要早起”“这周很忙”），有过期时间，最多 50 条

## 更新路径

复用现有的回写调用，**不额外增加模型调用**。回写 JSON 增加一个可选字段：

```json
"profile_updates": [
  {"key": "address_as", "value": "小满", "source": "叫我小满就行"},
  {"key": "health", "value": "最近感冒", "source": "我感冒了"}
]
```

代码侧校验（这是防幻觉的关键，不能只靠提示词）：

| 校验 | 行为 |
| --- | --- |
| `key` 不在白名单 | 丢弃，记 `profile_rejected` |
| 缺少 `source` | 丢弃 |
| 值为空 | 丢弃（绝不用空值覆盖） |
| 超长 | 截断 |
| 字段是列表 | 去重后追加，上限 20 条 |
| 命中禁止类别 | 丢弃，记 `profile_rejected_sensitive` |

## 注入提示词

`user_summary` 扩展成短段落，控制在 4 行内：

```
对方：小满（让它叫这个名字）
城市：杭州；作息：23:30-07:30；职业：设计师
在意：人得先照顾好自己
最近健康：感冒中（11-10 开始）
近期：明天要早起
```

原则：**只注入和当前场景相关的**。健康只在 `ongoing` 且用户提到相关话题时注入，
避免每条消息都提醒模型“他在生病”。

## 面板

人格卡片下方加「对方」区块：

- 画像字段（只读），健康项标为敏感
- 每条带来源原话，点开可见
- `observations` 显示最近 3 条及过期时间

编辑入口（阶段 A5）先不做。但必须有纠正途径——自动学习迟早出错，
至少先提供“清空画像”的按钮。

## 成本

- 模型调用：**0 次新增**（搭回写的车）
- 输出 token：每次回写多几十个 token
- 存储：每个画像文件几百字节

### A1/A2 实现要点

- 回写协议：`profile_updates: [{key, value, source}]`，解析阶段丢弃缺 `source` 的条目。
- 代码校验：`PROFILE_FORBIDDEN` 命中直接拒绝并记 `profile_rejected`；
  未知 key 记 `unknown_key`；空值记 `empty`。
- 列表字段去重后追加，上限 20；`health` 按文本去重，重复出现只刷新 `source`。
- `user_summary` 注入称呼、城市/作息/职业、在意、不喜欢、健康提示。
- 健康注入分三档：对方刚提到身体 → 可以问“好点没有”；48 小时内 → 只在相关时提；
  超过 48 小时且没提 → 不注入。
- 回写提示词也带上已知画像，避免重复询问。

## 已决事项

| 问题 | 结论 |
| --- | --- |
| 作息是否影响主动闸门 | **要做，但带概率**。人也会试探着发消息，所以到点后按低概率放行，不硬性静默 |
| 健康如何关心 | 只在“有问题/相关”时问。刚提到或 48 小时内的新情况才允许表达关心，避免好端端问“好点没有” |
| 画像是否跨会话共享 | **共享**。群聊和私聊里的同一个人就是同一个人，按 `user_id` 归并，不按会话隔离 |

### 实现共享画像时的注意点

现在画像存在 `state["user"]["profile"]`，即"人格 × 会话"级别。一人格一会话时等价于
"每人一份"。等支持一人格多会话（群聊 + 私聊）后，需要把画像搬到按 `user_id` 键控的
独立存储（例如 `user_profiles/<user_id>.json`），会话只保留临时状态（在睡、在哪、最后一句）。

这样拆分后：

- 画像：跨会话共享
- 临时状态：按会话隔离（群里的"去睡了"不应影响私聊状态）
- `user.user_id` 已经记录，拆分时可直接作为键
