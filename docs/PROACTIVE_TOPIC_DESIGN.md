# 主动消息的话题连续性设计

> 状态：**阶段 0（仅提示词）已实现**，其余阶段待做。
> 本文记录设计意图、状态机、落地顺序和验证方式，避免改动时丢失上下文。

## 问题

主动消息间隔较长（默认 90 分钟），模型倾向于接着上一次的内容说，导致：

1. 话题衔接生硬，总在追旧内容而不是自然地开新话题。
2. 用户没看到、没回复时，机器人会反复提同一件事。
3. 对话已经有明确结束信号（“明天再聊”“先去睡了”“我先忙”）后，仍然按日程找上来。

期望行为：模型自己判断该继续还是该换；该等待时不要重复；等太久就搁置；
下一次可能回头补一句，也可能自然开启新话题。

## 根因

| 原因 | 说明 |
| --- | --- |
| 提示词强制衔接 | 原规则要求“内容必须和对方最后说的话接得上，不要自顾自换话题”，等于每轮把话题拉回上次内容 |
| 缺少话题状态 | 只存了 `last_text`，没存“这个话题是否已结束/已搁置” |
| 未回应只做整体降速 | `unanswered` 累计到 3 才退避，不区分“没看到”和“不想回” |
| 结束信号只处理睡眠 | `user_state` 只识别去睡/出门，不处理话题层面的收尾 |

## 设计：会话阶段

四个阶段由事件和时间推导，不靠模型猜：

```
       用户发消息
          ↓
      ┌────────┐  机器人发出（尤其带问题）  ┌──────────┐
      │  open  │ ───────────────────────→ │ awaiting │
      └────────┘                            └──────────┘
          ↑                                      │ 超过 shelve_after
          │ 用户回来                              ↓
          │                                  ┌──────────┐
          │        任一方明确结束              │ shelved  │
          └────────────←──────────────────  └──────────┘
                          ↓
                     ┌────────┐
                     │ closed │  静默到 closed_until
                     └────────┘
```

| 阶段 | 进入条件 | 主动策略 |
| --- | --- | --- |
| `open` | 用户刚回复 | 可继续，也可自然换话题 |
| `awaiting` | 机器人发出消息且 `asked_question` | 宽限期内不重复；超时转为 shelved |
| `shelved` | awaiting 超过 `shelve_after_minutes` 无回复 | 可以主动，但**必须开新话题** |
| `closed` | 任一方出现结束信号 | 静默到 `closed_until`，之后只开新话题 |

原则：**“没看到”和“不想回”无法区分，所以一律不追问**。宁可搁置，不连发。

## 建议默认值

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `reply_grace_minutes` | 20 | 发出后多久内不重复发 |
| `shelve_after_minutes` | 90 | 多久没回算搁置 |
| `closed_quiet_minutes` | 120 | “先忙/有事情”类结束信号的静默时长 |
| `closed_until_morning` | 是 | “去睡了/明天再聊”静默到次日 07:00 |
| `comeback_probability` | 0.15 | 搁置后允许“回头补一句”的概率 |
| `closed_peek_probability` | 0.05 | 静默期内极小概率冒泡，仅非深夜 |

## 闸门增量

| 原因码 | 条件 |
| --- | --- |
| `awaiting_reply` | 阶段为 awaiting 且距上次发送小于宽限期 |
| `conversation_closed` | 当前时间早于 `closed_until` |

`unanswered_backoff` 保留作为兜底。

## 提示词改造（阶段 0 已做）

去掉强制衔接，改为按状态给建议：

- 上次主动没得到回应 → 不重复追问、不换个说法再问，可以等或聊无关的新事
- 对方已经回应 → 可自然接着聊，也可顺势说自己的事，不必强行回到旧话题
- 旧话题已自然收尾 → 不要硬接
- 分享自己正在做的事，通常比追问对方更容易接

阶段 0 不引入新状态，仅用现有数据推导：

```
awaiting_reply = last_sent_at > inbound.last_at
```

## 输出协议（阶段 5）

现在是“一句话或 SKIP”，计划扩展为：

```
CONTINUE: 接着上次的话
NEW: 开新话题的话
WAIT
```

解析容错：无前缀按普通消息处理；`shelved` 阶段记为 `NEW`。用于审计和话题更新。

## 新增状态（阶段 1）

```json
"conversation": {
  "phase": "open",
  "topic": "一句话话题摘要",
  "topic_since": 0,
  "last_bot_at": 0,
  "asked_question": false,
  "unanswered_streak": 0,
  "shelved_at": 0,
  "closed_until": 0
}
```

`topic` 由对话回写产出（回写本来就在读对话）；回写失败时退化为上次发送内容的截断。

## 验证方式

阶段 0 只需观察：

1. 连续两三条主动之间，是否还在复述同一件事。
2. 你故意不回，它的下一条是否还会追问同一个问题。
3. 你说“明天再聊”后，静默期内是否还会冒出来（这一步阶段 0 只能靠提示词约束，
   真正生效要等阶段 2 的闸门）。

阶段 2 之后可以用审计里的原因码验证：`awaiting_reply`、`conversation_closed` 是否按预期出现。
